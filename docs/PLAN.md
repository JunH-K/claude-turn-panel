# claude-turn-panel — PLAN

`docs/PRD.md`의 요구사항(R-N)을 만드는 순서와 완료 기준이다.

## 새 세션에서 시작하는 순서

1. `docs/PRD.md`를 읽는다. 요구사항과 결정 사항이 거기 있다.
2. 아래 단계 표에서 끝나지 않은 첫 단계를 찾는다.
3. 모드 코드를 고치기 전에 `plugin-authoring` 스킬을 불러온다. 이 빌드의 API 선언이 그 스킬에 딸려 온다.
4. 고친 뒤에는 "확인 방법"의 네 가지를 모두 돌린다.

## 확인 방법

네 가지를 모두 돌린다. 하나라도 실패하면 끝난 것이 아니다.

```bash
claude plugin validate .        # 선언과 훅을 엔진이 읽는 대로 검사
claude plugin test .            # tests/*.test.ts
tsc -p .                        # 타입 검사 (엔진이 .claude-plugin/types 를 깐 뒤)
claude --plugin-dir .           # 실제 세션에 띄워 본다
```

엔진이 타입 폴더를 아직 깔지 않은 폴더에서는 `tsc -p .` 대신 `plugin-authoring` 스킬이 준 선언 파일을 `include`에 넣은 임시 `tsconfig.json`을 폴더 밖에 두고 돌린다.

### 실제 세션 확인

`tmux`에 시험 세션을 띄우고 키를 보내 화면을 읽는다.

1. 요청을 보내면 패널이 열리고 요청 상자에 "진행 중"과 경과 시간이 뜬다.
2. 도구를 쓰는 동안 진행 상자의 한 줄이 바뀐다.
3. 끝나면 상태가 "완료"로 바뀌고 보고, 바뀐 파일, 다음 작업이 뜬다.
4. 대화 화면에 `next` 블록이 보이지 않는다.
5. `ctrl+x tab` 뒤 숫자를 누르면 그 제안이 다음 요청으로 나간다.
6. `e` 뒤 숫자를 누르면 입력란에 채워진다.
7. `p`, `n`으로 지난 턴이 넘어가고 지난 턴에서는 제안이 숨는다.
8. `/turn-panel off` 뒤의 턴에는 블록이 붙지 않고 패널이 열리지 않는다. `/turn-panel on` 뒤에는 돌아온다.
9. `ctrl+x x`로 닫으면 다음 턴에도 스스로 열리지 않고, `/turn-panel`로 다시 열린다.

2026-10-14에 1~9를 2.1.296에서 확인했다. 링크와 파일을 실제로 여는 것(cmux 브라우저 칸, WebStorm)과 좁은 터미널의 상태 줄 안내는 실제 세션에서 눌러 보지 않았고 테스트로만 확인했다.

설치본(0.2.1)으로 2026-10-14에 더 확인한 것:

- 링크 상자의 주소 단추(`Tab`으로 옮겨 `Enter`): cmux 브라우저 칸이 열리고, 두 번째 주소는 같은 칸에서 열린다.
- 링크 상자의 파일 단추: WebStorm이 그 파일을 연다(WebStorm 로그로 확인).
- 세션 폴더 밖 파일 단추: WebStorm으로는 열리지 않는다(로그에 기록 없음). 글 편집기 창이 떴는지는 화면 접근 권한이 없어 확인하지 못했다.
- 하위 에이전트: 시스템 프롬프트에 제안 지시문이 없다고 답했다(하위 에이전트의 자기 보고).
- 체크리스트: 시험 세션에서 모델에게 할 일 도구(TaskCreate, TodoWrite)가 주어지지 않아 실제 화면으로는 보지 못했다. 테스트로만 확인했다.

제안이 붙는 비율은 새 세션에서 쟀다(Haiku 기준: 수정 요청 3줄, 문서 한 줄 추가 2줄, 설명 요청 1줄, 인사 0줄). 오래 꺼 두었다가 켠 세션에서는 모델이 앞선 답변들의 모양을 따라가 한동안 제안을 빼먹을 수 있다.

## 설치와 배포

개발 중에는 `claude --plugin-dir .`로 그 세션에만 불러온다.

배포는 이 폴더를 GitHub 레포로 올리는 것이다. `.claude-plugin/marketplace.json`이 이 레포를 설치 출처로 만든다. 다른 맥에서는 터미널 세션의 입력란에 아래 한 줄을 친다.

```
/plugin install turn-panel --marketplace <owner>/<repo>
```

사용자 범위로 설치하면 그 맥에서 새로 여는 모든 대화형 세션에 적용된다. 끄려면 `claude plugin disable turn-panel@claude-turn-panel`, 지우려면 `claude plugin uninstall turn-panel@claude-turn-panel`이다. 이미 떠 있는 세션은 다시 켜야 반영된다.

## 리뷰 기록

2026-10-14에 두 번의 리뷰를 받았다.

- 보안 리뷰: 제안의 보낼 글이 화면에 안 보이던 것, 형식이 어긋난 블록이 어디에도 안 보이던 것을 고쳤다. 같은 관점에서 파일의 기본 앱 열기를 글 편집기 열기로 바꿨다(R-9, R-10, R-25).
- 독립 코드 리뷰(19건): 턴이 끝날 때 파일 확인을 기다리던 것(높음)과 중간 8건, 낮음 10건 가운데 아래를 뺀 전부를 고치고 사례마다 테스트를 더했다.
- 공개 전 보안 검사(8건): 슬래시 명령 제안을 입력란 채우기로 바꾸고(높음), 유니코드 공백·길이·`!`로 보낼 글을 숨기는 길, 실행 파일로 가는 본문 파일 링크를 막았다(중간). 다음 작업 상자를 보고 위로 옮기고, 블록을 가리는 조건을 좁히고, 제안이 바뀐 직후의 누름을 버리고, 지시문에 출처 제한을 넣고, 짧은 주소가 호스트를 줄이지 않게 했다(낮음).
- 커밋 보안 검사: 본문 파일 링크의 확장자 허용 목록이 바로가기와 실행기 확장자로 우회될 수 있어, 본문에서 파일 링크를 아예 없애고 링크 상자의 단추(편집기로만 연다)로 옮겼다.
- 커밋 보안 검사 2: 모델이 적은 세션 폴더 밖 파일(바로가기 포함)이 IDE로 열려 그 프로젝트 설정이 불려 올 수 있어, IDE는 세션 폴더 안의 실제 경로일 때만 쓰고 밖은 글 편집기로 연다(R-27).
- 원격 화면 점검: 모드가 여는 브라우저 칸·편집기는 세션이 도는 맥에 뜬다. 원격 화면에서는 보는 쪽이 링크를 열게 바꿨다(R-28). 처음에는 사용자가 말한 "링크가 안 열림"의 원인으로 짐작했으나 아니었다. 그 세션은 0.2.1 설치 전에 모드를 불러온 상태였다.
- 사용자 제보(보고의 표가 패널에서 깨짐): 엔진이 패널 안의 표를 터미널 폭으로 그린다. 처음에는 표를 행마다 세로 목록으로 폈으나 사용자가 표 모양을 원해서, 표를 칸 상자(퍼센트 폭)로 직접 그리게 바꿨다(R-29).
- 커밋 보안 검사 3: 모델이 직접 쓴 `file:` 링크(마크다운 링크, 꺾쇠 링크, 참조 정의, 4천 자 넘는 줄)가 본문 링크로 남아 cmd+클릭으로 기본 앱이 열릴 수 있어, `http(s)`가 아닌 링크는 글로 풀었다(R-13). 턴이 끝날 때 모델이 적은 경로를 스스로 확인하다 `/net/…`의 자동 네트워크 마운트를 일으킬 수 있어, 세션 폴더와 홈 폴더 안의 경로만 확인한다(R-14).
- 커밋 보안 검사 4: 링크 풀기가 참조 정의 꼴, 코드 울타리 판별 차이로 우회될 수 있었다. 문법을 따라가지 않고 글 전체에서 `file:` 주소가 될 글자 줄을 끊는 마지막 단계(`defuseFileLinks`)를 더했다(R-25). 코드 안의 `file:`은 `file :`로, `&#`는 `\&#`로 보인다.
- 커밋 보안 검사 5: `mayStat`은 경로 글자만 보고, `fs.stat`은 바로가기를 따라가 세션 폴더 안의 `/net/…` 바로가기로 마운트가 일어날 수 있었다. 경로 확인을 `fs.list`로 폴더를 하나씩 내려가며 바로가기 없이 닿는 보통 파일만 받게 바꿨다(R-14). 바로가기로 된 파일은 링크 상자에 나오지 않는다.
- 커밋 보안 검사 6: 모델이 쓴 `[믿을 만한 글](다른 주소)`와 `http(s)` 참조 정의가 그대로 남아 보이는 글과 다른 곳을 여는 링크가 될 수 있었다. 모델이 쓴 링크는 `safeUrl`을 거쳐 누르는 글자를 실제 주소로 다시 쓰고, 참조 정의는 모두 글로 풀었다(R-13).
- 고치지 않고 적어 둔 것: 하위 에이전트의 시스템 프롬프트(PRD 6절), 복원 뒤의 기록(PRD 5절), 다른 owner의 `owner/repo#N`을 걸지 않는 것(R-14).
