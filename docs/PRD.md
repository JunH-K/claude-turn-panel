# claude-turn-panel — PRD

Claude Code 세션 안에 패널을 하나 띄워, 그 세션의 요청과 완료 보고를 한 묶음으로 보여 주고 다음 작업을 고르게 하는 모드(플러그인 이름 `turn-panel`)다.

## 1. 배경

세션을 여러 개 켜 놓고 오가며 쓴다. 한 세션에 돌아왔을 때 "여기서 무엇을 요청했고, 무엇이 끝났고, 다음에 뭘 하면 되는지"를 알려면 대화를 거슬러 올라가 읽어야 한다. 요청은 위로 밀려 올라가 있고 보고는 길다.

이전에 같은 이름의 모드를 만들어 썼다가 2026-10-14에 지웠다. 그때의 불만은 디자인이었다. 글자가 모두 같은 굵기와 색이라 요청·보고·제안이 한 덩어리로 보였고, 제목과 내용 사이의 여백이 없었다. 답변 끝에 제안 블록이 대화 화면에 그대로 보이는 것도 거슬렸다.

## 2. 목표

세션에 돌아온 순간, 대화를 거슬러 올라가지 않고 패널만 보고 다음 세 가지를 안다.

1. 무엇을 요청했는가
2. 무엇이 끝났는가 (또는 지금 무엇을 하는 중인가)
3. 다음에 무엇을 하면 되는가, 그리고 왜 그것인가

마우스 없이 키보드만으로 패널에 가서 고르고 돌아올 수 있어야 한다.

## 3. 요구사항

| 번호 | 요구사항 |
| --- | --- |
| R-1 | 사람이 낸 요청만 요청으로 친다. 하위 에이전트의 턴과 엔진·다른 세션이 넣은 글(작업 알림 등)은 치지 않는다. 패널에서 고른 제안은 사람의 요청으로 친다. |
| R-2 | 본 세션의 턴이 정상 종료하면 그 턴의 요청과 최종 답변을 한 묶음으로 저장한다. 세션마다 최근 20턴을 둔다. `/clear`를 하면 기록도 비운다. 막혀서 들어가지 못한 요청은 요청으로 남기지 않는다. |
| R-3 | 패널은 구획마다 둥근 테두리 상자로 나눈다. 상자의 첫 줄이 제목(강조색 굵은 글씨)이고 그 아래가 내용이다. 구획은 위에서부터 요청, 다음 작업(턴이 도는 동안은 진행), 보고, 링크, 바뀐 파일 순서다. 다음 작업을 보고보다 위에 두는 것은 보고가 길어도 고를 글이 화면 밖으로 밀려나지 않고, 보고 본문에 상자를 흉내 낸 글이 있어도 진짜 상자가 먼저 보이게 하기 위해서다. |
| R-4 | 요청 글은 줄바꿈을 살려 그린다. 이어진 빈 줄은 하나로 줄이고, 8줄을 넘으면 접고 "… n줄 더"를 붙인다. |
| R-5 | 요청 상자 제목 오른쪽에 상태와 시각을 보인다. 끝난 턴은 "✓ 완료 · 3분 전 · 2분 14초", 도는 턴은 "⏵ 진행 중 · 1분 12초"다. 정상 종료하지 못한 턴은 "중단됨", "오류", "모델이 거절함"으로 보이고 직전의 정상 보고를 그대로 둔다. |
| R-6 | 턴이 도는 동안 진행 상자를 보인다. 첫 줄은 지금 하는 일 한 줄(도구 호출을 "파일 읽는 중" 같은 말로 바꾸고 대상을 흐리게 붙인다)이다. 호출이 여럿 겹쳐 돌면 가장 늦게 시작한 것을 보이고, 끝난 호출의 줄만 지운다. 모델이 할 일 목록을 만들면 그 아래에 체크리스트(완료, 진행, 대기)를 보인다. 체크리스트는 그 턴에서 할 일 도구를 쓴 턴에만 보인다. 앞선 턴에서 다 끝내지 못한 목록을 무관한 턴에 끌고 오지 않는다. |
| R-7 | 턴이 도는 동안 직전 턴의 보고를 "직전 보고"라는 흐린 제목으로 아래에 남긴다. 제안 상자는 숨긴다. |
| R-8 | 그 턴에서 고치거나 새로 만든 파일을 "바뀐 파일" 상자에 나열한다. 성공한 호출만, 같은 파일은 한 번만 적는다. 검토하도록 보류된 변경은 적지 않는다. 하위 에이전트가 고친 파일도 넣는다(일을 맡기는 구성에서도 무엇이 바뀌었는지 보여야 한다). 턴이 도는 중에도, 중단·오류로 끝난 턴에도 그때까지 고친 파일을 보인다. 새로 만든 파일은 표시한다. 8개를 넘으면 접는다. 누르면 편집기로 연다. |
| R-9 | 모델이 답변 끝에 쓴 제안 블록을 읽어 "다음 작업" 상자에 최대 3개를 보인다. 제안마다 짧은 문구(굵게), 근거, 보낼 글을 보인다. 보낼 글은 줄이지 않고 그대로 보인다(`/`로 시작하면 "명령"이라고 경고색으로 적는다). 문구만 보이면 문구와 다른 글이 나가도 고르는 사람이 알 수 없다. 보낼 글이 300자를 넘거나 `!`로 시작하면 블록 전체를 버린다. 이어진 공백은 유니코드 공백까지 하나로 줄인다. 블록에 3개보다 많이 적혀 있으면 몇 개가 더 있는지 알린다. |
| R-10 | 대화 화면에서는 제안 블록을 빼고 그린다. 저장된 답변 원문은 건드리지 않는다. 가리는 것은 패널이 대신 보여 줄 때뿐이다: 패널이 화면에 놓여 있고, 블록이 선택창으로 옮겨지는 형식이고, 그 글이 패널의 기록에 든 턴의 최종 답변일 때만 뺀다. 아직 닫히지 않은 블록은 턴이 도는 동안(쓰는 중)만 뺀다. 그 밖의 경우(패널이 닫혔거나 놓이지 못함, 형식이 어긋남, 도구 호출 사이의 중간 글, 중단된 턴의 글)에는 모델이 쓴 글을 그대로 둔다. |
| R-11 | 숫자 키 `1`~`3`은 그 제안을 사용자 요청으로 바로 제출한다. `/`로 시작하는 제안은 실행하지 않고 입력란에 채운다. 사용자가 Enter를 치는 것이 두 번째 확인이다(모델이 쓴 명령은 플러그인 설치까지 할 수 있다). 같은 제안이 두 번 나가지 않게 한 번 고르면 선택창을 감춘다. 막혀서 나가지 못하면 선택창을 되돌린다. 제안이 바뀐 지 1.5초 안의 누름은 버리고 알린다(읽던 제안이 손가락 밑에서 바뀌는 것을 막는다). |
| R-12 | `e`는 "고쳐서 보내기"를 켠다. 켠 상태에서 숫자를 누르면 제출하지 않고 입력란에 채운다. 한 번 채우면 풀린다. 채우면 키보드가 입력란으로 돌아간다. |
| R-13 | 보고 본문에서 `http(s)` 주소, 앞에 `http`가 없는 주소 꼴 글자(`github.com/…`, `www.…`), `#123`과 `owner/repo#123`을 누를 수 있는 링크로 바꾼다. 파일 경로는 본문에서 링크로 걸지 않고 모아서 링크 상자에 둔다(R-24, R-25). 코드블록 안은 건드리지 않는다(목록이나 인용 안에 들여 쓴 것, 더 긴 울타리 안의 것 포함). 모델이 링크 문법으로 직접 쓴 링크(`[글](주소)`, `<주소>`, 그림)는 주소를 검사해, 누르는 글자가 언제나 실제 주소가 되게 다시 쓴다: 글과 주소가 같으면 그대로, 다르면 `글 (실제 주소)`로 쓰고 괄호 안의 주소만 누를 수 있다. 검사를 통과하지 못한 주소(`http(s)`가 아닌 것, 계정 정보가 든 것 등)는 링크를 풀어 글만 남긴다. 참조 정의 줄은 모두 글로 푼다. 보이는 글과 다른 곳을 여는 링크를 막는다(2026-10-14 커밋 보안 검사 6)(R-25). `sh`·`so`·`app`·`dev`·`me`처럼 파일 확장자와 겹치는 도메인은 경로가 붙었거나 `www.`로 시작할 때만 주소로 본다. 4천 자를 넘는 줄은 훑지 않고, 그 줄의 `[`와 `<`를 글자로 만들어 링크가 되지 않게 한다. |
| R-14 | `#123`은 세션 폴더의 git 원격이 GitHub일 때만 건다. `owner/repo#123`은 그 owner가 세션 저장소의 owner와 같을 때만 건다(`and/or#1`, `feature/login#2` 같은 글자가 남의 저장소로 걸리지 않게 한다). 파일 경로는 실제로 있는 파일일 때만 건다. 있는지 확인하는 것도 세션 폴더나 홈 폴더 안의 경로뿐이고 `..`이 든 경로는 확인하지 않는다. 확인은 사람이 누르기 전에 스스로 도는데, `/net/<호스트>/…` 같은 경로를 들여다보기만 해도 맥이 그 호스트로 네트워크 마운트를 시도하기 때문이다(2026-10-14 커밋 보안 검사). 확인할 때 바로가기를 따라가지 않는다. 세션 폴더(또는 홈)에서 그 파일까지 폴더를 하나씩 목록으로 읽고(목록은 항목 자체의 종류를 알려 주고 따라가지 않는다), 중간 폴더나 파일이 바로가기면 그 경로는 확인하지 않는다. 엔진의 `fs.stat`은 바로가기를 따라가므로, 받아 온 저장소에 `/net/…`을 가리키는 바로가기가 있으면 확인만으로 마운트가 일어난다(2026-10-14 커밋 보안 검사 5). 저장소와 파일을 찾는 일은 턴이 끝난 뒤에 따로 돌고, 파일 하나를 2초 넘게 기다리지 않는다. 그동안 보고는 링크 없이 먼저 보인다. |
| R-25 | 파일은 늘 편집기로 연다. 편집기 명령이 없을 때와 편집기 옵션이 `system`일 때는 맥의 기본 글 편집기로 연다(`open -t`). 파일의 기본 앱으로 열지 않는다. 경로는 모델이 쓴 글에서 오는데, 기본 앱으로 열면 스크립트나 앱이 실행될 수 있다. 같은 이유로 보고 본문의 파일 경로는 터미널 링크로 만들지 않는다. 본문 링크는 cmd+클릭하면 터미널이 파일의 기본 앱으로 열고, 확장자로 거르는 것은 바로가기(심볼릭 링크)나 실행기에 묶인 확장자로 우회된다(2026-10-14 보안 검사). 모델이 링크 문법으로 직접 쓴 `file:` 링크도 막는다. 마크다운 문법(링크, 참조 정의, 코드 울타리)을 따라가며 거르면 렌더러와 읽는 방식이 어긋나는 틈이 남으므로, 패널에 넘기는 보고 글 전체에서 `file:` 주소가 만들어질 수 있는 글자 줄(대소문자, 사이의 탭, `\:`, 문자 참조 `&#…;`·`&이름;`)을 끊는다. 이 렌더러가 링크로 그리는 주소는 `http(s)`와 `file`뿐이다(2026-10-14 커밋 보안 검사 4). |
| R-15 | 주소 링크는 cmux 브라우저 칸에서 연다. 이 세션이 이미 연 칸이 있으면 그 칸의 주소만 바꾸고, 없거나 닫혔으면 새 칸을 연다. 사용자가 따로 열어 둔 브라우저 칸은 건드리지 않는다. cmux 밖에서는 본문 링크의 클릭을 가로채지 않고 화면의 원래 동작에 맡긴다. 파일 링크와 바뀐 파일은 편집기에서 연다(줄 번호가 있으면 그 줄로). |
| R-16 | `p`와 `n`으로 지난 턴 묶음을 넘겨 본다. 지난 턴의 제안은 고를 수 없게 글로만 보인다(대화 화면에서 가린 블록이 여기 남는다). 새 턴이 시작하거나 끝나면 최신으로 돌아온다. |
| R-17 | 단축키 안내는 패널 맨 아래에 흐린 글씨로 작게 둔다. |
| R-18 | `/turn-panel`은 패널을 연다(키보드 초점과 함께). 이미 열려 있으면 닫는다. 사용자가 닫으면 다시 열 때까지 스스로 열리지 않는다. |
| R-19 | `/turn-panel off`는 모드 기능을 끈다: 패널을 닫고, 스스로 열지 않고, 제안 블록 지시문을 시스템 프롬프트에서 뺀다. `/turn-panel on`은 다시 켠다. 켜고 끄기는 그 세션에만 적용되고 새 세션은 켜진 채 시작한다. |
| R-20 | 평소에는 턴이 시작하거나 끝날 때 패널이 스스로 열린다. 터미널이 좁아 놓이지 못하면 상태 줄에 여는 명령을 알린다. |
| R-21 | 패널은 본문 64칸을 요청한다. 사용자가 직접 맞춰 둔 폭이 있으면 그것이 이긴다(엔진의 규칙). |
| R-22 | 화면 없는 실행(`claude -p`, SDK)에서는 아무 일도 하지 않는다: 지시문을 넣지 않고, 기록하지 않고, 타이머를 걸지 않는다. 팀원 에이전트의 시스템 프롬프트에도 지시문을 넣지 않는다. 하위 에이전트는 지시문의 마지막 문장으로 막는다(시스템 프롬프트에서 가려낼 표시가 선언에 없다. 6절 참고). |
| R-24 | 보고 본문의 링크를 "링크" 상자에 단추로 다시 늘어놓는다. 본문 안의 링크는 클릭으로만 눌리고 Tab이 닿지 않으므로, 키보드로 여는 길은 이 상자다. 8개까지 보이고, 바뀐 파일 상자에 이미 있는 파일은 다시 적지 않는다. cmux 밖에서 이 단추를 누르면 맥의 기본 브라우저로 연다. 링크가 없으면 상자도 없다. |
| R-26 | 지시문은 제안의 출처를 사용자가 이 대화에서 직접 말한 목표로 한정한다. 파일, 웹 페이지, 도구 출력의 지시나 문구를 제안 글로 옮기지 않고, push·배포·삭제·외부 전송처럼 되돌리기 어려운 일은 제안하지 않으며, 슬래시 명령은 사용자가 이 세션에서 직접 쓴 것만 적게 한다. 고른 글이 사용자가 친 말로 제출되기 때문이다. |
| R-27 | 파일을 IDE(WebStorm·VS Code·Cursor)로 여는 것은 실제 경로(바로가기를 다 푼 것)가 세션 폴더 안에 있을 때뿐이다. 밖의 파일은 글 편집기(`open -t`)로만 열고 그렇다고 알린다. IDE는 파일을 열 때 그 파일이 든 프로젝트의 설정(실행 구성, 작업, 확장)도 함께 불러오므로, 모델이 적은 남의 프로젝트 파일을 IDE로 열면 그 프로젝트의 코드가 돌 수 있다(2026-10-14 보안 검사). 없는 파일은 열지 않고 알린다. |
| R-28 | 세션을 데스크톱 앱·웹·모바일로 원격에서 볼 때는 링크를 보는 쪽 화면이 연다. 모드가 여는 cmux 브라우저 칸과 편집기는 세션이 도는 맥에 뜨므로 원격으로 보는 사람에게는 아무 일도 안 일어난 것처럼 보인다. 원격 화면에서는 본문 링크를 가로채지 않고, 링크 상자의 주소는 보는 쪽이 여는 링크로, 파일은 누를 수 없는 글로 보인다. 제안 고르기는 그대로 된다. |
| R-29 | 보고 본문의 마크다운 표는 패널 폭에 맞춘 표로 그린다. 칸마다 폭을 나눠 주고(글이 긴 칸이 넓게), 칸에 다 안 들어가는 글은 그 칸 안에서 줄을 바꾼다. 머리글은 굵은 글씨에 패널 제목 색을 입힌 보통 글로 그리고(터미널 글꼴에 따라 한글 굵은 글씨가 보통 글씨와 구분되지 않는다. 2026-10-14 실제 화면), 머리글 아래와 행 사이는 흐린 가로줄로 나눈다. 세로줄은 넣지 않는다(글자로 그린 세로줄은 여러 줄로 늘어난 칸에서 끊기고, 상자 테두리는 한 면만 그릴 수 없다. 사용자가 지금 모양으로 정했다). 칸 안의 링크는 본문 링크와 똑같이 눌린다. 엔진의 마크다운 요소는 패널 안의 표를 패널 폭이 아니라 터미널 폭에 맞춰 그려서, 패널보다 긴 줄이 꺾여 표가 깨지기 때문이다(2026-10-14 사용자 제보, 실제 세션에서 재현). 처음에는 표를 행마다 세로 목록으로 폈으나, 사용자가 원한 것은 표 모양을 지키는 것이었다(2026-10-14). 울타리 코드블록 안의 표는 건드리지 않는다. |
| R-30 | 턴이 끝나 제안이 있으면 첫 제안의 요청 글을 입력란의 흐린 제안으로 띄운다. `Tab`으로 받으면 입력란에 채워지고, 사람이 읽고 Enter로 보낸다. 엔진이 스스로 짐작한 흐린 제안이 오면 첫 제안으로 바꿔 넣는다. 슬래시 명령 제안은 띄우지 않는다. 입력란에 글이 있거나 턴이 도는 동안에는 엔진이 띄우지 않는다. 모드를 끄면 엔진의 짐작을 그대로 둔다(2026-10-14 사용 분석: 제안 114번 중 3번만 골랐다. 패널로 가서 고르는 길이 멀다). |
| R-31 | Claude가 질문하고 답을 기다리며 끝낸 답에도 블록을 쓴다. 이때 한 줄은 사용자가 할 답 하나다: 문구는 답의 요지, 근거는 그 답을 고르면 어떻게 되는지, 요청 글은 그대로 보낼 답이다. 되돌리기 어려운 일(push, 배포, 삭제, 외부 전송)을 승인하는 답은 넣지 않는다. 사용자가 직접 친다(2026-10-14 사용 분석: 요청의 27%가 20자 이하의 짧은 답이다). |

| R-23 | 실패는 패널을 멈추지 않고, 모드는 도구 호출과 턴을 붙잡지 않는다. 제안 블록이 없거나 형식이 어긋나면 "제안 없음"만 보인다. 링크나 파일을 열지 못하면, 고른 제안이 다른 훅에 막혀 나가지 못하면 알림(toast)으로 알린다. 모드의 훅이 실패해도 도구 호출과 턴은 그대로 진행된다. 패널을 여는 일과 경로·저장소를 찾는 일은 기다리지 않고 턴을 넘긴다. |

### 제안 블록 형식 (R-9)

답변 맨 끝의 `next` 코드블록이다. 한 줄이 제안 하나다.

````
```next
짧은 문구 | 근거 한 문장 => 그대로 제출될 요청 글
```
````

- `=>` 왼쪽이 선택창에 보이는 쪽, 오른쪽이 제출되는 글이다. 왼쪽은 `|`로 문구와 근거를 나눈다. 근거가 없는 줄(`문구 => 요청 글`)도 받아서 근거 없이 그린다.
- 최대 3줄을 쓴다. 더 쓰면 앞의 3줄만 쓴다.
- 문구나 요청 글이 빈 줄이 하나라도 있으면 블록 전체를 버린다. 보이는 글과 제출되는 글이 달라 보이게 만드는 문자(제어 문자, 그려지지 않는 문자)가 있어도 버린다. 고르는 사람이 보낼 글을 정확히 알고 골라야 하기 때문이다.
- 버린 블록은 가리지 않는다. 대화 화면과 패널의 보고 본문에 모델이 쓴 그대로 보인다.
- 인사나 단순 문답에는 블록을 쓰지 않는다. 질문으로 끝나는 답에는 답 고르기 블록을 쓴다(R-31).

## 6. 제약

- 모드 API는 얼리 액세스라 Claude Code 버전마다 바뀔 수 있다. 2.1.296에서 만들고 확인했다.
- 패널 폭은 요청일 뿐이다. 사용자가 맞춰 둔 폭(`~/.claude.json`의 `pluginPanes.dockColumns`)이 이긴다.
- 모드가 스스로 패널을 열 때는 터미널이 144칸(그 패널을 한 번 연 뒤에는 110칸) 이상이어야 놓인다. 명령으로 열면 어떤 폭에서도 놓인다.
- 패널 단축키는 패널이 키보드를 쥐고 있을 때만 먹는다. 입력란에서 패널로 가는 키는 엔진의 `ctrl+x tab`이고 돌아오는 키는 `Esc`다.
- 링크 누름을 모드가 받는 것은 터미널이 클릭을 알려 주는 전체 화면 모드에서다.
- 보고 본문(마크다운) 안의 링크는 클릭으로만 눌린다. Tab과 방향키는 단추에만 닿는다.
- 선언의 `PromptComposeTrait`에 하위 에이전트를 가리키는 값이 없어 모드가 직접 가려내지는 못한다. 2026-10-14 실제 세션에서 하위 에이전트는 자기 시스템 프롬프트에 지시문이 없다고 답했다(자기 보고라 완전한 증거는 아니다). 지시문 마지막 문장("서브에이전트는 이 블록을 쓰지 않는다")도 함께 막는다.
- 사용자가 닫기 키로 닫는 길(`ui.close`의 `person`)은 테스트 도구로 일으킬 수 없어 실제 세션에서만 확인했다.
- 체크리스트는 모델이 할 일 목록 도구(`TaskCreate`·`TaskUpdate`·`TodoWrite`)를 쓸 때만 생긴다.

"실행" 칸에 ○가 있는 줄은 실제 세션에서 돌려 본 것이고, 빈칸은 선언만 읽은 것이다. 2.1.296 기준이다.
